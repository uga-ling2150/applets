## Anonymous attempt history

Each activity assigns a random browser participant, with up to 20 separately identified attempts. Refresh resumes the saved unfinished attempt; an explicit new attempt creates a separate record. Teacher-only history includes incomplete/discarded/completed attempts, task actions, client-reported UTC times and server receipt/submission UTC times. CSV downloads separate attempts from event history. Public comparisons expose neither action histories nor submission timestamps. Receipts use an internal collection reference, participant number and attempt number; they locate a record only when a student voluntarily supplies their receipt, not a verified identity. Clearing storage, private browsing or changing devices can create a new participant. Existing pre-history submissions have unknown timestamps and are shown as such.

Only allowlisted task events are stored: page open/reload/leave, start/pause/resume, marker/undo/discard, completion/retry, transcript/comparison views, practice start/end and audio waiting/errors. No free-text content, keystrokes, student names, emails, IPs or fingerprints are written to classroom records. Hosting processes network requests as usual. Events use a persistent local outbox and bounded batches (40); retries deduplicate event IDs. Abrupt browser termination, unavailable browser storage or clearing unsynced data can lose events, so this is not a guaranteed exhaustive or tamper-proof audit. Limits are 1,000 events per attempt or participant-level stream, and 20,000 per activity. Records expire after 30 days.

## Functional consistency review — independent student computers

Students use the fixed course URL independently on their own computers. No activity code is displayed or requested, and no teacher creation step is required. Each browser generates a separate random participant key automatically; the service assigns a P number. Refresh retains that browser’s participant and server-confirmed receipts within the current collection. These are browser records, not verified identities. A browser lock prevents simultaneous editing in two tabs of the same profile; it does not coordinate separate students’ computers.

The service serializes automatic collection provisioning. All allowlisted teachers can view current and unexpired previous course collections. An optional “Start next collection” control separates a later class; it is not a prerequisite for using the page. Collections expire after 30 days; the fixed URL then provisions a new collection. A closed collection stays closed until a teacher reopens or replaces it. Existing private test rooms remain separate.

Prior exposure now persists after practice or opening/closing the transcript and includes repeated listening; practice marker events are not uploaded. CSV exposure column names describe this broader meaning. Personal CSV repeats retain the same P number with a local attempt index, distinct from the server's A number (which can also include discarded attempts). Successful submission clears the stale submitting status; closed-room text states submissions are closed. Log quota/permanent errors stop automatic retry and display the actual failure. Removing teacher authorization invalidates existing sessions. The shared CSS feedback-followed modifier yields a measured 24px inter-card gap while retaining the standard 2150 teaching cards.

## Teacher-led classroom listening (2026-09-23)

Open the normal 7A page and choose **Join classroom listening**, or append `?mode=live`.
The existing individual-listening mode remains the default and keeps its data and workflow.

1. Sign in with the existing authorized GitHub account. Choose a recording, then **Prepare new classroom**.
2. Share the displayed student link. It fixes the collection/recording; students need neither login nor headphones. Wait for the browser count to reach the expected class size.
3. Use this teacher computer for the classroom speakers. **Start class listening** gives a three-second countdown, then plays the loaded recording. Keep the tab visible and the computer awake. Students click or focus the response button and press Space/Enter.
4. Pause/resume from the teacher page. Buffering, hiding the teacher tab, or a lost teacher connection pauses playback. Student marking is disabled when synchronization is stale. Reconnect and resume rather than rewinding; use a new classroom for a new pass.
5. At the natural audio end, student records submit automatically, including zero-marker records. Share the classroom comparison and download its CSV. Use the classroom-session selector to revisit earlier sessions. Download before the displayed collection expiry date.

The frontend uses `live.js` and the pure `live-clock.js`; the existing Worker dispatches `/live`, `/live-control`, `/live-join`, `/live-save`, and `/live-results` to `src/live.mjs`. Classroom sessions and participant records use separate `live:` and `live-record:` storage keys. They do not change the legacy `run:`, `attempt:` or individual comparisons. There are up to 20 classrooms per collection and 60 browser participants per classroom. For more sessions, use the original teacher tools to start a new collection. Retention is the parent collection's existing 30-day expiry, not a new 30-day period for each classroom.

Synchronization uses a 500 ms state poll and teacher audio-position heartbeat. Clients estimate server time from the lowest-round-trip sample in the recent window, then extrapolate the teacher's actual audio position with `performance.now()`. They do not start timers on message arrival or use server receipt time as the click time. Marking stops after two seconds without a state response, 2.5 seconds without a fresh teacher anchor, or an estimated round trip of 800 ms or more. This is classroom discussion timing, not a laboratory-grade synchronization guarantee. A sudden audio pause or network loss can take up to the polling/freshness window to propagate. Speaker/device latency is not calibrated.

Polling was chosen for this bounded implementation to reuse the existing HTTP/authentication and Durable Object architecture. No new platform, Cloudflare binding, secret, database migration, or WebSocket infrastructure is required. Polling is limited to open classroom pages; close these pages after class. Changed click snapshots are locally persisted and saved with increasing sequence numbers. Retries and older snapshots cannot overwrite newer data, completed records are immutable, and another browser cannot fetch a participant's saved record. A browser lock prevents two tabs from recording into the same browser record. Teacher control requires both existing authorization and a controller lease to prevent competing tabs.

Classroom CSVs include session, recording, anonymous participant, marker seconds, completion, transcript use, late joining and submission time. Public released comparisons exclude submission timestamps. Classroom mode does not collect the individual mode's detailed action log. Results are descriptive, not verified attendance or a validated experiment. Students who refresh retain saved clicks and join the current time; those joining after playback begins are flagged.

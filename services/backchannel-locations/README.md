Teachers use “Sign in with GitHub” to view submitted counts, export CSV/JSON and release anonymous comparisons. No separate course password is created. Legacy rooms without an owner remain accessible only to approved teachers who know the old room code; their old bearer links alone no longer authorize access. Login uses PKCE, a browser-bound state cookie, a single-use 60-second handoff and an eight-hour server-side session. The frontend holds its opaque session token in sessionStorage; sign-out revokes the session. The browser never receives the application secret. GitHub's own consent and reauthentication screens remain under GitHub's control.

Configure teacher IDs and client ID, run `wrangler secret put GITHUB_CLIENT_SECRET --config services/backchannel-locations/wrangler.jsonc`, then `wrangler deploy --config services/backchannel-locations/wrangler.jsonc`. Changing the owning Cloudflare account requires deploying there and updating the frontend API origin and OAuth callback. Removing a teacher ID blocks both new sign-ins and existing sessions on their next authorization check.

Anonymous browser keys identify a participant within one activity; each completed attempt is immutable, and retries of the same attempt are idempotent. Switching browsers or clearing storage can create a second participant, so this is a discussion tool rather than attendance verification. Names, emails, voices and reflections are not collected by the app. The host processes ordinary network requests. ## Anonymous attempt history

Each activity assigns a random browser participant, with up to 20 separately identified attempts. Refresh resumes the saved unfinished attempt; an explicit new attempt creates a separate record. Teacher-only history includes incomplete/discarded/completed attempts, task actions, client-reported UTC times and server receipt/submission UTC times. CSV downloads separate attempts from event history. Public comparisons expose neither action histories nor submission timestamps. Receipts use an internal collection reference, participant number and attempt number; they locate a record only when a student voluntarily supplies their receipt, not a verified identity. Clearing storage, private browsing or changing devices can create a new participant. Existing pre-history submissions have unknown timestamps and are shown as such.

Only allowlisted task events are stored: page open/reload/leave, start/pause/resume, marker/undo/discard, completion/retry, transcript/comparison views, practice start/end and audio waiting/errors. No free-text content, keystrokes, student names, emails, IPs or fingerprints are written to classroom records. Hosting processes network requests as usual. Events use a persistent local outbox and bounded batches (40); retries deduplicate event IDs. Abrupt browser termination, unavailable browser storage or clearing unsynced data can lose events, so this is not a guaranteed exhaustive or tamper-proof audit. Limits are 1,000 events per attempt or participant-level stream, and 20,000 per activity. Records expire after 30 days.

## Functional consistency review — independent student computers

Students use the fixed course URL independently on their own computers. No activity code is displayed or requested, and no teacher creation step is required. Each browser generates a separate random participant key automatically; the service assigns a P number. Refresh retains that browser’s participant and server-confirmed receipts within the current collection. These are browser records, not verified identities. A browser lock prevents simultaneous editing in two tabs of the same profile; it does not coordinate separate students’ computers.

The service serializes automatic collection provisioning. All allowlisted teachers can view current and unexpired previous course collections. An optional “Start next collection” control separates a later class; it is not a prerequisite for using the page. Collections expire after 30 days; the fixed URL then provisions a new collection. A closed collection stays closed until a teacher reopens or replaces it. Existing private test rooms remain separate.

Prior exposure now persists after practice or opening/closing the transcript and includes repeated listening; practice marker events are not uploaded. CSV exposure column names describe this broader meaning. Personal CSV repeats retain the same P number with a local attempt index, distinct from the server's A number (which can also include discarded attempts). Successful submission clears the stale submitting status; closed-room text states submissions are closed. Log quota/permanent errors stop automatic retry and display the actual failure. Removing teacher authorization invalidates existing sessions. The shared CSS feedback-followed modifier yields a measured 24px inter-card gap while retaining the standard 2150 teaching cards.

Regression evidence: 25 automated cases (backend, validation and frontend behavior). A newly created empty dedicated live test activity, 9C27UMBR, received 60 concurrent synthetic browser clients: 60 distinct P numbers, 60 saved submissions, and each client rejoining recovered only its own receipt. The teacher CSV contained 60 distinct participants. This is simulated client concurrency against the live service, not a 60-physical-computer exercise. Real Chrome verified new code creation, existing P1/A1 and P1/A2 receipt recovery after refresh, foreground clipboard copy/paste, and a second tab unable to record while the original tab remained usable.

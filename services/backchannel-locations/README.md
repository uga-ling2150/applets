# Activity 7A: Backchannel Locations

Static course page: `docs/week_7/7A_backchannel_locations.html`; assets under `docs/week_7/7a/`. The page and audio are hosted on GitHub Pages. Individual/offline mode keeps work in browser localStorage (best effort), with JSON export/import for up to 60 participants. Online class mode uses the independent `ling2150-7a-classroom` Cloudflare Worker and SQLite Durable Objects. There are no student accounts or model downloads.

Run `node --test services/backchannel-locations/tests/core.test.cjs services/backchannel-locations/tests/classroom.test.mjs` from the repository root. Build a standalone HTML with embedded audio/CSS/JS using `python3 services/backchannel-locations/scripts/build.py <output.html>`. Bootstrap for that build is vendored under `services/presumptive-grounding/vendor/`.

Recordings are continuous AMI headset excerpts under CC BY 4.0; see `docs/week_7/7a/ATTRIBUTION.txt`. Timed transcripts and signal checks are complete, but human listening confirmation of sound quality and microphone bleed is still outstanding. Do not represent the recordings as validated experimental stimuli. Marker times include listener and device latency. The 15-second practice reuses the opening of the selected clip and therefore gives prior exposure to that opening.

JSON imports are bounded and validated before replacing existing results. Duplicate IDs are skipped; conflicting IDs reject the import. Zero-marker completed rounds remain in the denominator. The cluster table counts each participant at most once per one-second interval. No scoring or ground-truth backchannel labels are supplied.

Verification (2026-09-19): six validation/aggregation tests passed. Real Chrome playback confirmed keyboard marking, pause protection, practice exclusion, reload/resume, a completed marked round and a completed zero-marker round, correct comparison denominator, clip isolation, JSON download with reflection, and duplicate import rejection. A 320 px viewport had no horizontal overflow. Signed-in axe DevTools Pro 4.136.1 / axe-core 4.13.0, WCAG 2.1 AA and best practices enabled, reported zero automatic issues in the playback and expanded comparison/transcript states. This does not constitute full manual accessibility certification. Direct file:// execution and real classroom use have not been verified.

## Online classroom collection

Teacher: expand “For teachers”, choose a clip and create an activity. Save the private teacher link; share only the student link/code. Students each use their own browser, listen once and automatically submit a completed round. The teacher views/refreshes results, downloads JSON/CSV, and can close collection and release the anonymous comparison to the class. Both roles need an internet connection for classroom collection. The embedded HTML still supports local practice without a server.

The teacher link contains a random bearer key in its URL fragment. Anyone holding it can control that room; it is not an identity login. Save it privately: losing the link and browser storage means losing management access. Students have random per-browser participant keys. Only key hashes are stored server-side; no name, email, voice recording or reflection is collected by the app. The hosting provider still processes network requests. Submitted fields are clip version, participant number, random record ID, marker seconds and transcript/comparison exposure. A completed empty-marker round counts as a participant.

Limits: 60 browser participants per activity; 300 markers each; 30-day expiry (storage alarm deletes the room); 100 activity creations/day across this service. Free account quotas are shared, and no paid upgrade is enabled. Refreshing/retrying with the same browser key does not duplicate the record; first submission is immutable. Clearing browser storage or switching browsers can create another participant. This is an anonymous classroom discussion aid, not authenticated attendance or grading. Teacher release makes results readable to anyone holding the room code; closing alone keeps them teacher-only.

Deploy from the repository root with `wrangler deploy --config services/backchannel-locations/wrangler.jsonc`. No frontend GitHub token or Cloudflare account credential is shipped. The service currently runs in the existing project Cloudflare account; the public GitHub repository holds source, not classroom records. Moving ownership requires deploying this service in the destination account and updating the API origin in `docs/week_7/7a/classroom.js`.

Classroom verification: 11 local tests passed. A deployed-service test with 60 simultaneous synthetic students preserved all 60 records, rejected unauthorized reads before release, deduplicated retries, and exercised release/reopen controls. This is a bounded concurrency test, not a guarantee about every classroom network.

Real Chrome classroom flow also verified: teacher creation, student link joining without login, full-length playback and automatic submission, teacher result retrieval and CSV download, teacher release, and student comparison access after reload without a duplicate submission. Signed-in axe Pro reported zero automatic issues in the student submitted state and the teacher results/control state (WCAG 2.1 AA).

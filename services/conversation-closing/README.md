# Activity 10A model service

The student page is `docs/week_10/10A_conversation_opening_closing.html`. Its JavaScript and CSS are in `docs/week_10/10a/`. GitHub Pages serves the page. This separate Cloudflare Worker performs live inference; it does not change the 7B service. Both strategies use the same model and settings. The server prepends the same four-turn fictional exchange to every request so the shared starting context cannot be edited in the browser request.

Run `npm test` and `npm run build` here. The build produces the optional standalone Worker page in `public/index.html`. Deploy with `npx wrangler deploy`. GitHub Pages does not deploy the Worker. `ENABLED` starts as `false` for initial deployment; configure `SESSION_SECRET` with `npx wrangler secret put SESSION_SECRET` (a unique random value of at least 32 bytes), then set `ENABLED` to `true` and redeploy. Never commit secrets. Check `/api/health` and make live requests through the published page before classroom use. Update `API` in `docs/week_10/10a/applet.js` if the Worker address changes.

The Worker stores request counts and temporary request leases in a Durable Object, not conversation text. The model receives the shared fictional exchange and conversation history for the side being answered. Predictions, observations and reflection notes remain in the browser tab. The public endpoint uses signed anonymous sessions and global limits; CORS is not user authentication. These app limits (600/day, 24/session by default) do not guarantee provider capacity. Do not enable billing automatically. If the service must be paused, set `ENABLED=false` and redeploy; the clearly labelled offline example remains available.

The differences prompted between assistants are tendencies, not guaranteed results. The initial identical user message allows a controlled first-reply comparison; subsequent conversations may diverge. See `CLOUDFLARE_HANDOVER.md` at repository root for classroom and transfer instructions.

Verification before the course-page publication: six service tests passed; the live Worker returned replies for both strategies with the same softly closing message. With an explicit “Bye,” both strategies closed, as the page explains. A hosted-browser check confirmed keyboard submission, both live replies, reflection download and no 320 px horizontal overflow. axe-core 4.13.0 found zero automatic WCAG 2.1 A/AA or best-practice violations in the local initial, two-reply and reset-confirmation states and in the hosted two-reply state. This does not replace manual screen-reader testing or a classroom-network rehearsal.

Activity: Recognizing Coreference

Learning Objectives
  • Analyze how linguistic features are used to identify named entities and coreference relationships
  • Experiment with a (weak) named entity recognition, coreference resolution, and entity linking tool to explore the difficulties inherent in the task
Background

During conversations with chatbots, chatbots must be able to recognise names of people, places, etc. that are named in the conversation, track mentions across turns (including pronouns), and link them to external databases. This applet simulates this process, using Wikidata as the external database, and a very lightweight system to detect named entities and coreference relations between noun phrases.

It basically detects the following coarse-grained entity types only:
HUMAN_MALE HUMAN_FEMALE PERSON ORG PLACE OTHER

It then attempts to connect each of them to the corresponding entry in Wikidata. When a new turn appears that contains a pronoun, the system tries to connect it to previous references to named entities.

Because this applet simulates the entity-related modules ONLY, it does not produce any turns. You must enter both the human and AI turns yourself, and the system will act as if it had to do the same analysis for AI and human turns.

Note: If you wish to look at the Wikidata entry, go to https://www.wikidata.org/wiki/[Wikidata_ID]. For example, Wikidata's page on Paris is at https://www.wikidata.org/wiki/Q90.

Instructions

  1. Try the demo conversation. What do you notice? Does the system make any mistakes? If it does, where in the pipeline did the error arise, and what type of linguistic information could have been used to make the correct decision?
  2. Now try typing in your own conversations. Have one groupmate play the role of the human, and another play the role of the AI. What happens? Can you spot any errors?

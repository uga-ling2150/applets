# Activity 9A audio and timing data

Five continuous excerpts from the AMI Meeting Corpus (manual annotations v1.6.2) are used in `9A_turn_taking_trps.html`. The original meeting headset mixes are ES2003b and IS1005c. Source ranges, target speakers, and changes are credited in the page's source card. The audio files are 16 kHz mono WAV with per-excerpt gain and a 20 ms edge fade. Each excerpt ends before the next speaker's annotated word onset.

`data.js` holds the shifted manual word boundaries, a 96-bin amplitude display, the annotated final word ending and the original next-speaker onset. The annotated word boundaries are approximate, particularly around disfluencies. The last word ending is an analysis reference, not the only possible TRP. Student clicks are judgments in a browser, not measured speech onsets; their offsets must not be called gaps or overlaps.

Independent practice does not upload student choices. Classroom listening uses the existing 7A service and shared clock, with separately namespaced TRP recordings and sessions. Individual results and locally imported group files use browser storage; the JSON export allows teachers to combine up to 60 anonymous participants on one computer. The optional group import has automated validation tests, but its native file-picker interaction still needs a manual browser check.

Before classroom release, listen to all five excerpts for clarity, prosodic cues, and accidental next-speaker leakage. Review the cuts and the AMI transcript, especially excerpt 4's fragmented words. If a clip is replaced, change the data version in `core.js` so old imports are rejected.


## October 7 classroom revision

The default entry is teacher-led classroom listening. Students open the teacher’s link for each excerpt, listen to classroom speakers, and press one response button with a mouse, Space or Enter. No waveform, playback progress, or automatic transcript is displayed during judgment. The optional transcript remains available as listening support and its use is recorded. `?mode=practice` retains independent listening and local JSON import; its waveform and progress appear only after a recording ends.

Teachers sign in through the existing GitHub allowlist, select one of five excerpts, prepare a classroom and share its session-specific link. Play through the teacher computer, then share the comparison. For the next excerpt, choose that recording, prepare a separate classroom and share the new link. Each excerpt’s records remain separate. Previous sessions can be selected for review. Results use translucent dots against click offset in seconds and a native text-count table; they do not lay out individual participant timelines. Zero-choice participants are included. CSVs contain both audio-relative click time and offset from the annotated final word ending.

Excerpt 2 already contains multiple TCUs: after “that sounds like a rough idea” (around 6.42 s), the same speaker continues with a question. Its internal completion is a discussion example, not a second answer key; the final annotated turn end remains the common offset reference.

`live.js` adapts the existing Backchannel classroom frontend; the clock is loaded directly from `week_7/7a/live-clock.js`. The Worker’s recording manifest adds five TRP IDs. Existing Backchannel sessions, authorization, retention and schema are preserved. The backend enforces one TRP choice per session. Do not publish the new frontend against an old Worker: deploy the updated `services/backchannel-locations/wrangler.jsonc` first, then publish static files. No new binding, migration or secret is required. Authentication returns only to one of the two fixed course pages; it never accepts an arbitrary return URL.

Offline/practice downloads remain local. Classroom records expire after 30 days. Browser keys are pseudonymous, not verified student identities. Click offsets include reaction time and uncalibrated network/device latency; neither negative nor positive offsets are measured speech overlap or gap. Marking pauses when synchronization becomes stale. Keep the page open until submission succeeds, or download pending work.

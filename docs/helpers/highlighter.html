Weighted Highlighter

What it's for

Lots of simple language models work by giving every word or short phrase a number, called a weight. A positive weight nudges a text toward one label; a negative weight nudges it toward the other; a bigger number means a bigger nudge. This tool shows those weights right inside a piece of text, so students can see what a model is "noticing", and start asking whether it is noticing the right things.

It's a shared building block: any applet can use it with its own list of words and weights. The demo below uses a made-up list that tells manager-speak apart from casual chat. Instructions for writing your own list are further down the page.

Try it

  1. Type or paste something into the box, or press Try an example.
  2. Look at what lights up, and what doesn't. Amber pushes toward manager-speak, teal toward casual chat, and a stronger colour means a bigger weight.
  3. Try other forms of the same word. Does "circling back" count as "circle back"? Does "synergies" count as "synergize"?
  4. Turn on Show weights and read the tally under the box. Can you write a sentence that a person would call manager-speak, but the tally calls casual (or the other way round)?

    Using it in your own applet

    Writing a weights list

    A weights list is a small block of JSON. Here is the one the demo uses, shortened:

    {
  "labels": { "positive": "Manager-speak", "negative": "Casual chat" },
  "minWeight": 0.3,
  "weights": {
    "circle back": 5.0,
    "synergize": 7.5,
    "low-hanging fruit": 5.6,
    "kpi": 7.04,
    "lol": -4.8,
    "hang out": -3.9,
    "gonna": -3.6
  }
}
    • weights (required): one line per word or phrase, written as "word or phrase": number. Positive numbers push toward the first label, negative numbers toward the second. The further from zero, the stronger the push and the stronger the colour. An entry of exactly 0 is never highlighted.
    • Numbers are written plainly: 2.5, -1, 0.75. No quotation marks around them, no plus sign, and a dot (not a comma) for decimals.
    • Words can be written however is natural. Capitals, accents and punctuation are ignored, so "Low-hanging fruit" and "low hanging fruit" are the same entry. With word-form matching on (the default), "circling back", "circled back" and "circle back" are the same entry too. If two entries turn out to be the same, the first one is used and the tester above tells you which ones were skipped.
    • Phrases can be any length. When phrases overlap, the longest one wins ("circle back" beats "circle" and "back"), each word belongs to at most one highlight, and a phrase never stretches across the end of a sentence.
    • Contractions and slang stay as written: "gonna" matches "gonna", not "going to", and "don't" matches "don't" or "dont", not "do not". List both forms if you want both.
    • labels (optional): short names for the two directions. They appear in the key, the match table and the tally ("the text leans Manager-speak"), so pick names that read well after "leans". If you leave them out, they are "Positive weight" and "Negative weight".
    • minWeight (optional, default 0): entries closer to zero than this are not highlighted. Useful for hiding hundreds of tiny weights in a list exported from a real model.
    • lemmatize (optional, default true): set it to false to match exact word forms only, for example if the model you are showing was trained on words exactly as written.
    • JSON is picky: use straight double quotes (", not curly ones from a word processor), put a comma between entries but not after the last one, and don't add comments. The tester above points out most mistakes.

    Colour strength is measured against the biggest weight in the whole list, not just in the current text, so a word always looks the same however much else is typed. Even the smallest weights stay visible (15% strength), and the underline always shows which direction a word pushes.

    Getting weights out of a trained model (technical)

    For a scikit-learn TfidfVectorizer plus LogisticRegression, a word's weight is its IDF value times the model's coefficient for it. This is what the original prototype worked out in the browser; now you do it once, in Python:

    import json

terms = vectorizer.get_feature_names_out()
idf = vectorizer.idf_
coef = model.coef_[0]      # two classes: positive = model.classes_[1]

weights = {t: round(float(i * c), 2) for t, i, c in zip(terms, idf, coef)}
# Keep the 200 strongest so the list stays readable.
weights = dict(sorted(weights.items(), key=lambda kv: -abs(kv[1]))[:200])

with open("weights.json", "w") as f:
    json.dump({"labels": {"positive": model.classes_[1], "negative": model.classes_[0]},
               "weights": weights}, f, indent=2)
    • With more than two classes, use model.coef_[k] for the class you want to show; every other class then counts as the "negative" direction.
    • If the vectorizer saw words exactly as written (no lemmatizing), set "lemmatize": false so the highlighter matches the way the model reads.
    • The tally just adds up the weights of the matches. It leaves out word counts, length normalization and the model's intercept, so it shows what the model notices rather than recreating its exact score. That simplification is deliberate.

    Adding it to a page

    1. Put the weights list in the page, inside a script tag with type="application/json" and an id. Keeping it in the page means it works even when the file is opened straight from a computer.
    2. In the applet card, add a labelled text box and an empty .hl-output box. The key, tally line and match table are optional; leave out any you don't need.
    3. At the end of the page, load Compromise (for word-form matching), the shared script, and start it.
    <script type="application/json" id="my-weights">
{ "labels": { "positive": "Formal", "negative": "Informal" },
  "weights": { "regarding": 2.1, "gonna": -3 } }
</script>

    A weights file in its own .json file also works, but only once the page is on GitHub Pages (browsers block it when a page is opened straight from a computer). If a list has a problem, the highlighted-text box shows what went wrong instead of staying blank.

    Highlighter.attach returns a promise of a controller with setText(text), setShowWeights(on), setWeights(list) and the current matches, for applets that want to drive it from their own buttons. Highlighter.find(text, Highlighter.prepare(list)) gives the matches without drawing anything.
